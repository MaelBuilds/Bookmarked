# Bookmarked — Product Spec

> _"Catch me up to exactly where I am — no spoilers."_

---

## Problem

Readers who take long breaks between sessions lose narrative context. They either:
- Re-read pages they've already read (time-consuming)
- Google summaries and accidentally hit spoilers
- Give up on the book

No existing tool respects the exact story position of the reader.

---

## Target User

Someone who reads physical books or e-readers casually — reads in bursts, weeks between sessions, cares about the story but doesn't want to backtrack or be spoiled.

---

## Core Value Proposition

A spoiler-free summary of a book, anchored to the exact point the reader is at — requiring minimal input.

---

## User Flow

### Happy Path
1. User opens app
2. Takes a photo of their current page
3. App identifies the book and anchors to the passage
4. App returns a spoiler-free summary: plot so far, active characters, where things stand

### Fallback 1 — Book not recognized from page
1. App prompts: _"We couldn't identify the book. Can you photograph the cover or spine?"_
2. User photographs cover or spine
3. Book identified via vision model → re-anchors to original page photo
4. Summary generated

### Fallback 2 — Still can't anchor precisely
1. App prompts: _"What chapter are you on?"_
2. User types chapter number or name
3. Summary generated up to that chapter

---

## Technical Approach

### Vision layer
- GPT-4o or Gemini Vision to OCR the page photo and extract a meaningful passage
- Same model to read cover/spine and extract title, author, edition

### Book identification
- Primary: LLM recognizes book from passage text directly
- Secondary: Extract title/author from cover → query Open Library API or Google Books API for ISBN + edition metadata

### Spoiler-free summary
- Prompt strategy: pass identified book + anchoring passage to LLM
- Prompt instructs: summarize plot, characters, and narrative state *up to and including this passage only* — no foreshadowing, no hints beyond this point
- Confidence check: if book unrecognized or passage ambiguous, trigger fallback before generating summary

### Stack (MVP)
- **Frontend:** Simple mobile-first web app (Next.js) or React Native for camera access
- **Backend:** Node or Python API layer handling vision + LLM calls
- **APIs:** OpenAI (GPT-4o), Open Library (book metadata fallback)
- **Auth:** None for MVP — stateless, no user accounts

---

## MVP Scope

### In
- Single-photo flow (current page)
- Two-photo fallback (cover/spine)
- Chapter input fallback
- Spoiler-free summary output
- Mobile web (camera access via browser)

### Out (v1)
- User accounts / reading history
- Bookshelf / library tracking
- Social or sharing features
- E-reader integrations (Kindle, Kobo)
- Offline support
- Non-English books

## Open Questions & Risks

| # | Question | Risk level |
|---|---|---|
| Q1 | How accurate is LLM spoiler boundary enforcement? Needs testing across genres | High |
| Q2 | Copyright — are book summaries generated by AI legally safe to serve? | Medium |
| Q3 | Generic passages (short chapters, dialogue-heavy) may not anchor reliably | Medium |
| Q4 | Obscure / self-published books not in LLM training data — fallback hits more often | Low for MVP |
| Q5 | Camera quality on low-end phones — OCR accuracy degrades | Low for MVP |
